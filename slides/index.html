Incidencias perdidas en correos y hojas de cálculo

  • O todo el mundo ve todo, o nadie ve nada.

Arquitectura · API

Monolito modular con Clean Architecture

composition inyección de dependencias, elige el driver de BD
http · infrastructure Fastify, Drizzle, argon2, reloj
application casos de uso, puertos, AuthorizationPolicy
domain entidades, máquina de estados · sin dependencias

domain ← application ← infrastructure / http ← composition

  • Las dependencias apuntan hacia dentro; ESLint lo comprueba en cada commit.
  • Errores tipados en la aplicación; solo http/ los traduce a códigos HTTP.
  • Contrato compartido con Zod en packages/shared: el front no redefine tipos.
  • PGlite en local y en tests, sin Docker; Neon (Postgres) en producción.
  • Render sirve API y front compilado; migraciones y datos demo al arrancar.

Las decisiones están en 9 ADR (docs/adr/): monolito modular, Clean Architecture, sesión en BD, PGlite y Neon, despliegue a coste cero, contrato Zod, adjuntos en bytea, atomic design y permisos en servidor.

Presentacionales

Átomos, moléculas y organismos reciben props y emiten callbacks. Sin fetch, sin router y sin sesión: solo las páginas usan datos.

Reglas que se comprueban

Un nivel solo importa de los inferiores. ESLint y un test de arquitectura fallan si alguien se lo salta.

Una story por pieza

Cada componente tiene su story y su test. Storybook se ejecuta en local con npm run storybook.

Solo las páginas usan TanStack Query, el router y la sesión. Los componentes reciben las allowedActions ya calculadas por la API y deciden únicamente qué mostrar.

Calidad y seguridad

Lo que protege la demo en cada cambio

Tests
≈ 3.000

Vitest en los tres paquetes: dominio, casos de uso, API con fastify.inject y componentes con Testing Library. La matriz de permisos es una tabla de tests.

CI en cada PR
lint› typecheck› test› build› e2e

4 flujos E2E con Playwright: login por rol, flujo completo, acceso denegado y Dirección sin acciones. Con PGlite temporal, nunca contra producción.

Husky, lint-staged y commitlint antes de cada commit.

Seguridad
  • Contraseñas con argon2id.
  • Sesión en BD, cookie httpOnly, secure, Lax, rotada al entrar.
  • Límite de intentos de login.
  • Toda entrada validada con Zod; el cliente no decide rol, estado ni autor.
  • Historial y auditoría solo de inserción.

Definition of Done de cada tarea: un test por criterio de aceptación, typecheck, lint y test en verde, una story por componente nuevo y revisión sin hallazgos graves pendientes.

AGENTS.md

Fuente de verdad para cualquier agente: stack, capas, seguridad y Definition of Done.

5 subagentes

6 skills

Recetas: SDD, ejecutar una tarea, caso de uso, componente, ADR y entrega.

Hooks y permisos

Formateo, archivos protegidos, typecheck al terminar; push e instalar piden permiso.

Revisores con contexto limpio: reciben solo el ID de la tarea y el diff, nunca el razonamiento de quien la implementó. Front y back en paralelo en worktrees de git cuando el contrato ya existe.

Proceso con IA · Evidencias

Los revisores encontraron lo que los tests no veían

security-reviewermedia

Un email de 1 MB podía llenar la base

El login no limitaba la longitud del email y cada intento fallido se guardaba en la auditoría, que no se borra. Unos cientos bastaban para agotar el plan gratuito de Neon.

Máximo de 254 caracteres y recorte antes de auditar, con tests.

code + securitymedia

Carrera al editar y asignar

Se leía y autorizaba fuera de la transacción: con dos peticiones a la vez, el historial podía quedar desfasado y un Usuario editar una incidencia que ya no estaba abierta. Los 1.009 tests pasaban.

SELECT … FOR UPDATE dentro de la unidad de trabajo.

code-reviewermedia

Mensajes en inglés por un efecto lateral

Los errores de validación salían en español solo porque una ruta importaba algo de shared. Al corregirlo apareció un fallo de tree-shaking con todos los tests en verde.

Import explícito, sideEffects correcto y comprobación del bundle.

Todos están documentados en docs/proceso-ia/hallazgos-revisores.md, con el problema y la corrección.
